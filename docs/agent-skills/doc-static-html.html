What it does

Generates self-contained terminal-retro HTML documentation pages. Each output is a single .html file that works opened from disk, served from any static host, attached to an email, or dropped on a NAS. CSS and JS are inlined — no companion files.

The aesthetic is "man rendered to web": monospace-first, high-contrast, paper-and-ink by default — with phosphor green, amber CRT, and Solarized Light one click away in a header picker.

Features

  • Four themes: paper (default light), solarized, phosphor (terminal dark), amber (CRT dark), plus system-auto
  • In-page fuzzy search via Cmd+K — works offline, works under file://
  • Cross-page search for multi-page builds (same JSON index inlined in every page)
  • Mermaid diagrams (client-side rendering via CDN)
  • highlight.js syntax highlighting (client-side via CDN)
  • Datatype variable font for inline charts and sparklines
  • ASCII callout labels: [ NOTE ], [ TIP ], [ WARN ], [ DANGER ]

When to use

Use when the deliverable is a standalone documentation artifact — something to save, share, host, or hand off:

  • Documentation, runbooks, README-style pages, internal wikis
  • API docs, knowledge base entries, release notes, design specs
  • "Make me a doc page for X", "I need a one-pager I can email"

Do not use for conversational answers, Word docs, slide decks, spreadsheets, or interactive web apps.

Workflow

  1. Decide structure — single-page (under ~3,000 words, ≤6 sections) or multi-page (chaptered content).
  2. Compose body HTML — headings with ids, code blocks with data-filename, callouts, tables, Mermaid diagrams.
  3. Compose structural pieces — title block, TOC, manhead, search input, theme picker, pagenav.
  4. Inline the theme palette — all four palettes in CSS custom properties.
  5. Build search index — JSON array mapping every h2/h3 to heading text + body snippet, inlined into every page.
  6. Include CDN scripts — highlight.js (if code blocks), Mermaid (if diagrams), Fuse.js (if search).
  7. Assemble and save — substitute placeholders, write to docs/.

Output rules

All generated .html files go in docs/ at the project root. This is a hard rule, not a default. Single-page: docs/<slug>.html. Multi-page: docs/<slug>/index.html plus siblings.
